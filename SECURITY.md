# Security and trust boundary

Author: jperch1987

Authentication workers emit only fixed progress stages and safe errors to the local server. Timeout messages distinguish configuration, Python SDK loading, source credential loading, the STS request, and legacy federation. The diagnostic output contains no MFA codes, credential values, profile paths, or raw AWS responses. Request timeouts do not extend an authenticator code's validity.

This app is a credential-capable AWS role switcher and resource lookup tool for a trusted single-user desktop. CLI and lookup authentication use local IAM-user keys and fresh MFA codes. Console switching opens a normal AWS Switch Role link in the current browser and uses its signed-in AWS identity. It is not a centrally hosted or multiuser service, and it has not received an independent security audit or production certification.

## Data and permissions

The metadata reader reads the configured file before filtering fields and returns allowed profile metadata and derived links. Profile names, account IDs, role ARNs, source-profile names, MFA device identifiers, regions, and local paths can reveal organizational information. Prefer a metadata-only config and keep source credentials in your private AWS credentials file. The app never edits either source file.

For each **Get CLI credentials** request, the Python helper reads the selected source IAM user's long-term keys from the AWS credentials file or source config section. It requires a fresh six-digit MFA code and calls AWS STS `AssumeRole` without reusing an assumed-role credential cache. This flow does not support SSO, external credential processes, web identity, temporary source credentials, or role chaining. AWS checks the source identity, MFA, trust policy, optional external ID, and permissions. Enforce your organization's MFA requirements in AWS policies; an app-side code requirement does not replace them. [AWS STS MFA parameters](https://docs.aws.amazon.com/STS/latest/APIReference/API_AssumeRole.html)

The `/api/cli` response intentionally contains temporary STS keys and a session token inside shell command strings over loopback HTTP. The browser holds them in memory, displays them, and copies them only when requested. Source keys are never returned to the browser. Each request creates a new one-hour session; the resulting credentials can be reused until expiration without another MFA prompt. There is no background refresh.

The app does not intentionally persist CLI MFA codes or temporary keys to disk or browser storage. It clears the displayed exports and its references on profile changes, new authentication, refresh, failure, expiry, page hide, or **Clear credentials**. This is not guaranteed memory erasure or AWS session revocation. It cannot clear clipboard history, terminal history, or credentials already exported into a shell. Secrets can also exist in local process memory and pipes, browser request/response inspection, page content, and recording tools.

The CLI flow does not save selections. Legacy selection endpoints use only profile/config metadata in `.state/active-profile.json` and never restore CLI credentials. An installation upgraded from v1.3.0 may still contain sensitive browser-profile data in `.state/browser` or `browser/` under a custom state directory. This version neither loads nor automatically deletes that old profile. Keep it private and exclude it from repositories and shared files.

## Resource Lookup

A lookup accepts one exact resource query and 1–250 selected role profiles sharing the same configured source profile and resolved MFA device. It requires a fresh MFA code for each search. A separate short-lived Python worker obtains a 900-second MFA-authenticated IAM-user session with `GetSessionToken`, then uses it to assume each target role independently for 900 seconds. Different source/device groups require separate searches and codes. This does not reuse CLI exports, browser sessions, or credentials from a previous lookup, and does not change CLI MFA requirements.

`GetSessionToken` credentials have the source IAM user's permissions and can call `AssumeRole`; they carry MFA context into that role-assumption request. The worker uses those credentials only for target-role authentication. It supplies the configured external ID and a restrictive inline session policy for the exact read actions required by the selected lookup type. Existing source permissions and role trust still apply, and the target role must already grant those read actions. The policy example in [lookup-permissions.example.json](lookup-permissions.example.json) does not grant the source user permission to assume a role and is never installed automatically. [GetSessionToken permissions](https://docs.aws.amazon.com/STS/latest/APIReference/API_GetSessionToken.html), [AssumeRole session policies](https://docs.aws.amazon.com/STS/latest/APIReference/API_AssumeRole.html)

MFA enforcement at role assumption is distinct from MFA conditions on later resource requests. AWS documents that assumed-role credentials do not carry MFA context for individual downstream API policy checks. A resource policy with its own MFA requirement can therefore deny lookup even after successful role authentication. The app reports denial and never weakens the policy. [MFA-protected API access](https://docs.aws.amazon.com/IAM/latest/UserGuide/id_credentials_mfa_configure-api-require.html)

Lookup calls only the supported EC2, S3, RDS, Lambda, EKS, ElastiCache, Route 53, and Elastic Load Balancing read APIs. Regional resources are checked in each selected profile's configured region; S3 checks bucket ownership globally, and Route 53 hosted zones are global. Route 53 results are confirmed against the assumed account’s owned-zone listing. Lambda lookup uses `GetFunctionConfiguration`, not a code download. Load balancer lookup calls only `DescribeLoadBalancers` through the current and/or Classic API. Its clients use the fixed regional Elastic Load Balancing endpoint; it never follows returned load balancer DNS names or calls listener or target-group APIs. Classic responses can include listener details, which are discarded along with other non-displayed fields. Load balancer failure messages use fixed API-family labels and allowlisted error categories. Unknown AWS codes, raw exception messages, request IDs, signed requests, and endpoint URLs from exceptions are not returned; the browser groups the safe reasons for display. Raw service responses can contain more information than the displayed resource metadata; the worker returns only allowed result fields and safe statuses. Source keys, temporary user and role credentials, MFA values, raw errors, and Lambda environment variables are not included in lookup results or worker stdout.

Credentials remain in the worker's memory and are not intentionally persisted, returned to Node.js, or reused across searches. The worker has a nine-minute deadline, and the server terminates it after ten minutes. Cancellation stops the job. Requests are capped at 4 MiB and worker output at 32 MiB; pagination and per-profile result limits remain enforced. Any unfinished profile is reported explicitly. Temporary AWS credentials may remain valid until their 900-second expiration; process exit, cancellation, and clearing results are not AWS revocation or guaranteed memory erasure. SDK logging and credential-bearing error output must remain disabled.

Lookup metadata includes account IDs, profile names, regions, resource identifiers/names/ARNs, and coverage statuses; it can reveal client infrastructure. The server keeps only the most recent job's metadata in memory, expires it 10 minutes after completion, cancellation, or failure, and replaces it when another search starts. It writes no lookup results to server state or browser storage. **Clear results**, **Refresh**, page exit/reload, and display expiration clear browser references; clearing the display does not immediately delete the server snapshot. Stopping the server clears its memory. Screenshots, browser inspection, and other local software may retain the metadata.

Pagination, match caps, denied permissions, deadlines, and unsupported or unsearched scopes limit coverage. A partial or failed search must never be presented as proof that a resource is absent. Preserve per-profile statuses alongside confirmed matches, including when a bucket is found but its region cannot be read.

## Console switching

**Open AWS Switch Role** is a normal link to `https://signin.aws.amazon.com/switchrole`, opened in a new tab with the selected account and full role name prefilled. The link uses `noopener` and `noreferrer`. You review and click **Switch Role** on AWS yourself. The app does not install or launch another browser, automate AWS pages, copy cookies, or control the new tab.

The app's MFA field and local IAM source keys are not used for this Console link. AWS handles sign-in and any MFA prompts in your current browser. Role switching uses the browser's original sign-in identity, including when moving between roles; a new MFA challenge is not guaranteed for each switch. The form cannot switch from root or supply `ExternalId`, and limits the full role path/name to 64 characters. Review the final account and role displayed by AWS before working. [AWS Console role switching](https://docs.aws.amazon.com/IAM/latest/UserGuide/id_roles_use_switch-role-console.html)

The older `/api/console` federation endpoint remains available for compatibility but is not used by the Console link. It authenticates through STS and exchanges temporary credentials for an AWS sign-in URL. Treat that URL as a bearer credential: never log, share, screenshot, or copy it into a support report. The app does not intentionally persist its MFA codes, temporary keys, or federation tokens. Browser history and inspection tools can still retain a login URL. [AWS federation URL handling](https://docs.aws.amazon.com/IAM/latest/UserGuide/id_roles_providers_enable-console-custom-url.html)

## Network boundary

The server listens on `127.0.0.1` over HTTP. Host/origin checks, browser request checks, a restrictive Content Security Policy, anti-framing headers, no-store responses, and a per-process CSRF token reduce attacks from unrelated web pages. These controls are **not user authentication**: another local process or user able to reach the port can read metadata, obtain the token, and submit requests. CLI, lookup, and legacy federation authentication still need a valid MFA code. Another local process can also read a retained lookup snapshot. These controls are not sufficient isolation for a shared machine.

Keep the loopback binding. Do not expose the app with port forwarding, public tunnels, LAN listeners, reverse proxies, or shared hosting. TLS alone would not add missing user isolation or authorization. Stop the server when finished. Use operating-system permissions to protect the credentials, config, checkout, and any leftover browser-profile data from v1.3.0. These controls do not protect against local malware, privileged users, memory inspection, browser extensions, or recording tools.

CLI and lookup authentication need outbound HTTPS to AWS STS. Lookup also needs the selected service's AWS API endpoints; the legacy federation endpoint needs AWS's sign-in endpoint. The Python helpers use fixed AWS destinations and certificate verification; they do not honor custom endpoint or proxy overrides. Legacy federation refuses redirects. Networks requiring a proxy need an approved network configuration. Your browser needs access to AWS sign-in and Console pages. Local UI assets use no external fonts, scripts, or telemetry. Installing Python dependencies separately contacts your configured package source.

## Terminal boundaries

The five generated environment assignments contain temporary credentials and region settings. They apply only to the terminal where you paste them; they neither invoke Python nor clear older environment settings. Use a fresh terminal without existing AWS overrides, especially `AWS_PROFILE`, `AWS_DEFAULT_PROFILE`, and legacy `AWS_SECURITY_TOKEN`, or follow the README's cleanup instructions. Run `aws sts get-caller-identity` after applying credentials, and omit `--profile` on later commands using those exports.

Use a trusted checkout and config, and review what you paste. Disable shell tracing, avoid recording, and use a history policy that does not save pasted secrets. Clipboard history or synchronization can retain copied commands. AWS rejects expired credentials, but their text may remain in terminal history. An app authentication failure leaves credentials already pasted into a terminal unchanged.

Console switching and terminal credentials are independent. The optional terminal-only `aws_session.py` helper still prompts for MFA in the terminal; the five export lines do not invoke it. Follow your organization's access process and use least privilege.

## Distribution and maintenance

Distribute reviewed source through a repository or release channel clients trust. Keep real profile files, credentials, `.state/`, virtual environments, `node_modules/`, MFA codes, session tokens, private screenshots, and other runtime artifacts out of commits and release archives. In particular, never include an old v1.3.0 browser profile containing cookies or sign-in data.

Keep Node.js, Python, your browser, and the operating system patched. The Node.js server uses its standard library; `npm ci` removes the app's obsolete Playwright Node.js dependency when upgrading from v1.3.0. Previously downloaded Chromium binaries and the old browser profile are neither used nor automatically deleted; browser download caches may be shared with other projects. Install `requirements.txt` in a dedicated Python virtual environment. The setup scripts store only executable paths in platform-specific files under the ignored `.state` directory, and preserve existing profile and credentials files. Runtime installation is opt-in through `--install-runtimes` or `-InstallRuntimes`: it uses Homebrew, apt/official Node.js HTTPS downloads with a SHA-256 check, or WinGet. Review updates and recheck destination validation, command quoting, secret handling, and authorization behavior.

Automated tests use fixtures and mocked AWS responses. They do not establish that live AWS sign-in, MFA, or role policies work in your environment. Validate the supported operating systems before client distribution. Publish release identifiers and checksums through your trusted channel when distributing releases; these instructions do not themselves imply a release or checksum.

## Reporting a problem

Use the private security-reporting channel offered by the repository or your distributor, when available. This project does not currently specify a security contact or response-time commitment. Do not post credentials, tokens, cookies, browser-profile files, private configuration, or unredacted customer metadata in public issues. Provide a minimal reproduction with placeholder profiles and runtime versions. Revoke or rotate any exposed credentials through your organization's incident process.
